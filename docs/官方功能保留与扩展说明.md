# 官方功能保留与扩展说明

本文记录官方 ZbxTable v3.0.6 功能基线、本项目在此基础上的扩展，以及后续维护时需要遵守的兼容约定。

## 官方功能基线

后端路由以 [`api/v1/router.go`](../api/v1/router.go) 为准，官方路由清单保存在 `api/v1/testdata/official-v3.0.6-routes.txt`，测试 `TestAllOfficialV306RoutesRemainRegistered` 用来防止官方接口意外丢失。覆盖以下功能域：

| 功能域 | 后端位置 | 维护要求 |
| --- | --- | --- |
| 拓扑、实时状态和图表 | `internal/handler/topology.go`、`topodata.go`、`graph.go` | 保持官方拓扑查询、编辑、状态和图表接口可用。 |
| 主机、主机组、模板和监控项 | `host.go`、`host_group.go`、`template.go`、`item.go` | 保留主机筛选、详情、监控数据、模板和分组接口。 |
| 历史数据、趋势和导出 | `history.go`、`trend.go`、`graph.go`、`export.go` | 保持原有请求参数、响应结构和导出入口兼容。 |
| 告警、问题、规则和事件 | `alarm.go`、`problem.go`、`rule.go`、`event_log.go` | 保留告警处理、规则分发、屏蔽、状态和通知渠道。 |
| 报表、定时任务和执行日志 | `report.go`、`cron*.go`、`task_log.go` | 保留周期任务、邮件/企业微信通知与执行记录。 |
| Zabbix 多实例、用户和系统设置 | `zabbix.go`、`user.go`、`group.go`、`menu.go`、`system.go` | 扩展时沿用实例身份和权限体系，不替换官方管理能力。 |
| AI 分析与 Webhook | `ai.go`、`base.go` | 保持既有认证、告警处理和 Webhook 接口。 |

## 本项目增加的能力

- **Zabbix 实例管理**：支持新增、编辑、测试、启停和删除 API 实例，并查看 Webhook 安装状态。凭据由应用加密后保存。
- **设备巡检**：按实例、主机或主机组配置监控项、阈值、允许 IP/账号和日志匹配规则；可查看结果、汇总、导出和清理记录。
- **巡检报告**：展示 IP、主机名、CPU/内存/磁盘利用率、磁盘剩余量、时间偏差、登录失败、暴力破解和异常账号等信息。周报、月报按设备输出平均值，不展示逐日采样值。
- **部署维护**：提供 Linux systemd、Docker、Windows 安装/运行/卸载脚本，以及环境检查、更新和修复流程。新安装默认端口为 `8089`、数据库名为 `zbxtable_lg`。

Windows 安全日志由 Zabbix Agent 采集，再通过 Zabbix 日志监控项和触发器告警。ZbxTable 服务本身不会直接读取远端 Windows 主机的 Security 日志。

## 数据库隔离

所有 ZbxTable 自有表使用 `zbxtable_` 前缀。默认使用独立的 `zbxtable_lg` 数据库；如显式配置为 Zabbix 数据库，应用只管理自有前缀表。卸载时如选择清理数据库内容，脚本先展示目标库和表，再要求输入 `DELETE TABLES`；它只删除列出的 `zbxtable_` 表，不删除数据库、Zabbix 原生表或停止 Zabbix 服务。

## 兼容性和发布检查

1. 新增后端能力优先使用新路由或可选字段；修改已有接口时核对官方前端使用的 URL、方法、参数和响应格式。
2. 前端以官方 `zbxtable-web` 为基础构建，不以简化页面替换完整站点。发布前检查首页、JS/CSS、图片资源和服务端嵌入产物。
3. 保持官方路由回归测试；运行 Go 测试、静态检查、前端构建及 `git diff --check`。未能运行的检查应在发布记录中明确说明。
4. 数据库迁移只涉及 `zbxtable_` 表；不得对 Zabbix 原生表执行修改或删除。
