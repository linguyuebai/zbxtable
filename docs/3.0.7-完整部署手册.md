# ZbxTable 3.0.7 完整部署手册

本文是 ZbxTable 3.0.7 的交付部署说明，适用于从 GitHub Release 下载、上传完整压缩包到 Linux、Windows PowerShell 部署、前后端分别构建、与现有 Zabbix 共用数据库、启用设备巡检和配置日志告警的场景。

文中的命令默认使用 3.0.7。升级到其他版本时，把 `v3.0.7` 和 `zbxtable-v3.0.7` 替换为对应版本。

## 1. 部署前确认

### 1.1 推荐的生产拓扑

```text
浏览器
   │ 8088 或 Nginx HTTPS
   ▼
ZbxTable 3.0.7 ── Zabbix Server API
        │
        └── MySQL/MariaDB 或 PostgreSQL
              ├── Zabbix 原生表
              └── zbxtable_* 表
```

ZbxTable 可以和 Zabbix 共用一个数据库实例、一个数据库名称，但必须使用明确的表前缀和最小权限账号。ZbxTable 的巡检、报告和告警数据使用 `zbxtable_` 前缀，不删除或覆盖 Zabbix 的 `hosts`、`items`、`history`、`events` 等原生表。生产部署前必须备份数据库。

### 1.2 端口和权限

| 项目 | 默认值 | 说明 |
| --- | ---: | --- |
| ZbxTable Web | `8088/tcp` | 可在 `config/app.conf` 的 `httpport` 修改 |
| Zabbix API | `10051` 不是必需端口 | ZbxTable 通过 HTTP/HTTPS 访问 Zabbix API |
| MySQL/MariaDB | `3306` | 与实际数据库端口一致 |
| PostgreSQL | `5432` | 使用 PostgreSQL 时填写实际端口 |
| SSH | `22` | 仅用于上传和远程管理 |

ZbxTable 安装脚本只创建或管理名为 `zbxtable` 的服务，不会执行 `systemctl stop zabbix-server`，不会修改 Zabbix 配置文件，也不会自动删除 Zabbix 服务。

### 1.3 Linux 环境要求

推荐 Ubuntu 20.04/22.04/24.04、Debian 11/12、Rocky Linux 8/9、AlmaLinux 8/9、CentOS Stream。完整 TAR.GZ 已包含前端构建结果，服务器至少需要：

```text
Linux amd64 或 arm64
Go 1.24+
tar、gzip、curl、sha256sum、bash、Python 3
```

如果没有 Go 或基础工具，可以在安装命令中增加 `--install-deps`，脚本会根据 apt、dnf、yum、zypper 或 apk 安装最小依赖，并在 Go 版本低于 1.24 时安装 Go 1.24.0。完整发布包已有前端时不会安装 Node.js；只有重新构建前端时才需要 Node.js/npm。该操作只安装软件包，不启动或停止 Zabbix。

### 1.4 Windows 环境要求

Windows Server 2019/2022 或 Windows 10/11，要求 PowerShell 5.1+、Go 1.24+。如果 ZIP 中没有前端文件，还需要 Git、Node.js/npm；完整 Linux TAR.GZ 不建议在 Windows 上作为首选安装包。

Linux 优先使用：


## 3. 方式一：从 GitHub Release 一键部署 Linux

### 3.0.1 交互式安装管理菜单

使用下面的一条命令启动菜单，按提示输入数字即可选择安装系统服务、安装 Docker、卸载或退出。安装时可以输入 Release 版本标签和 Web 端口；卸载时可以选择保留或删除配置，并需要输入 `DELETE` 确认。卸载只处理 ZbxTable 服务、容器及文件，不会停止 Zabbix 或删除共享数据库。

```bash
curl -fsSL https://github.com/linguyuebai/zbxtable/releases/download/v3.0.7/install-release.sh | sudo bash
```

菜单默认选用 `v3.0.7`。若需要无人值守，继续使用本手册后续的命令行参数方式，例如 `--docker-install --port=8088`；可用 `--uninstall` 进入卸载流程，增加 `--purge` 可同时删除本地配置。

### 3.0 真正一行命令（环境检测、文件校验、安装、启动和输出）

以下命令会下载 3.0.7 安装器，并自动完成：基础环境安装、Go 版本检查、Release 文件下载、SHA256 校验、压缩包关键文件检查、源码编译、systemd 服务启用和启动状态输出。数据库密码仍会在安装配置阶段安全地交互输入，不建议把密码写进命令行历史。

```bash
curl -fsSL https://github.com/linguyuebai/zbxtable/releases/download/v3.0.7/install-release.sh | sudo bash -s -- --version=v3.0.7 --install-deps --install-root=/opt/zbxtable
```

安装器默认会启动 `zbxtable.service`。只安装不启动：

```bash
curl -fsSL https://github.com/linguyuebai/zbxtable/releases/download/v3.0.7/install-release.sh | sudo bash -s -- --version=v3.0.7 --install-deps --install-root=/opt/zbxtable --no-start
```

脚本输出中看到 `SHA256 verification passed`、`Installation complete` 和 systemd `active (running)` 后，再访问 `http://服务器IP:8088`。

安装结束时会输出访问地址、systemd 自启动状态、默认账号 `admin` 和初始密码 `Zbxtable`。首次登录后必须立即修改密码。若检测到活动的 UFW 或 firewalld，脚本会自动放行 Web 端口；未检测到活动防火墙时会提示手工放行。

### 3.1 Docker 一行部署

如果服务器选择 Docker，安装器会检查 Docker 环境；缺少 Docker 时增加 `--docker-install`，脚本会在 Ubuntu/Debian apt 环境安装 Docker Engine，构建包含前端的镜像，创建容器并进行网页健康检查：

```bash
curl -fsSL https://github.com/linguyuebai/zbxtable/releases/download/v3.0.7/install-release.sh | sudo bash -s -- --version=v3.0.7 --docker-install --port=8088
```

服务器已有 Docker：

```bash
curl -fsSL https://github.com/linguyuebai/zbxtable/releases/download/v3.0.7/install-release.sh | sudo bash -s -- --version=v3.0.7 --docker --port=8088
```

自定义端口，例如 9088：

```bash
curl -fsSL https://github.com/linguyuebai/zbxtable/releases/download/v3.0.7/install-release.sh | sudo bash -s -- --version=v3.0.7 --docker-install --port=9088
```

Docker 方式使用 `zbxtable` 容器名，配置目录默认为源码目录下的 `config/`，日志、下载和上传目录挂载到源码目录。数据库地址仍需填写在 `config/app.conf`；如果 Zabbix 数据库运行在宿主机，Linux Docker 容器不能使用 `127.0.0.1` 指向宿主机，应填写宿主机内网 IP 或 `host.docker.internal` 的可用映射地址。

Docker 检查命令：

```bash
sudo docker ps --filter name=zbxtable
sudo docker logs -f zbxtable
curl -i http://127.0.0.1:8088/
```

Docker 安装结束时会输出容器名、访问地址和默认账号密码，并自动为活动的 UFW/firewalld 放行自定义端口。

#### 网络受限时指定 Go 代理和 Docker 镜像

如果日志出现 `toolchain@v0.0.1-go1.24.3` 下载超时，说明 Go 正在尝试切换到额外下载的 1.24.3 工具链。本版本源码已移除该强制切换要求，使用已安装的 Go 1.24.0 即可。重新下载最新 Release 源码后再运行安装器；若 Go 模块下载仍超时，可显式指定可访问的 Go 代理：

```bash
curl -fsSL https://github.com/linguyuebai/zbxtable/releases/download/v3.0.7/install-release.sh | sudo bash -s -- --version=v3.0.7 --install-deps --go-proxy='https://goproxy.cn|https://proxy.golang.org|direct'
```

如果服务器没有 Go 1.24+，安装器默认从 `go.dev` 下载 Go 1.24.0，并自动尝试 `golang.google.cn` 镜像；也可以指定自己的 Go 压缩包镜像目录：

```bash
curl -fsSL https://github.com/linguyuebai/zbxtable/releases/download/v3.0.7/install-release.sh | sudo bash -s -- --version=v3.0.7 --install-deps --go-download-base='https://你的镜像地址/dl'
```

若 Docker 报错无法访问 `docker.io/library/golang` 或 `debian`，这是构建服务器访问镜像仓库超时。请先将可访问的、兼容 Docker Hub 镜像标签的 Go 与 Debian 基础镜像同步到可达仓库，然后通过参数指定：

```bash
curl -fsSL https://github.com/linguyuebai/zbxtable/releases/download/v3.0.7/install-release.sh | sudo bash -s -- --version=v3.0.7 --docker-install --port=8088 --go-image=你的镜像仓库/golang:1.24-bookworm --runtime-image=你的镜像仓库/debian:bookworm-slim --go-proxy='https://goproxy.cn|https://proxy.golang.org|direct'
```

镜像仓库地址由部署环境提供；如果服务器不能访问任何可用镜像仓库或 Go 代理，需要先开放外网/代理访问或在可联网主机预先拉取并导入对应镜像。脚本无法绕过网络本身不可达的问题。

### 3.1 直接部署最新正式 Release

```bash
curl -fsSL https://github.com/linguyuebai/zbxtable/releases/latest/download/install-release.sh \
  -o install-release.sh
chmod +x install-release.sh
sudo bash install-release.sh \
  --install-deps \
  --install-root=/opt/zbxtable
```

脚本执行顺序如下：

1. 访问 GitHub Release API，查找最新版本。
2. 下载 `source.tar.gz`。
3. 下载同名 `.sha256` 并校验。
4. 检查安装目录是否已存在。
5. 解压源码和前端文件。
6. 按 `--install-deps` 安装缺少的系统工具和 Go。
7. 创建或保留 `config/app.conf`。
8. 构建后端二进制。
9. root 环境下创建 `zbxtable` systemd 服务。

### 3.2 部署指定版本 3.0.7

```bash
curl -fsSL https://github.com/linguyuebai/zbxtable/releases/download/v3.0.7/install-release.sh \
  -o install-release.sh
chmod +x install-release.sh
sudo bash install-release.sh \
  --version=v3.0.7 \
  --install-deps \
  --install-root=/opt/zbxtable
```

安装脚本的常用参数：

```text
--version=v3.0.7       指定 Release 标签
--repository=a/b       指定 GitHub 仓库
--install-root=PATH    指定源码和脚本目录，默认 /opt/zbxtable
--install-deps         自动准备 Linux 依赖
--force                替换已经存在的安装目录（默认行为）
--no-overwrite         已存在时拒绝替换
--skip-checksum        跳过校验，不建议生产使用
--skip-frontend        跳过前端构建，仅运行 API 模式
--help                 显示帮助
```

### 3.3 首次配置数据库

安装过程中若不存在配置文件，脚本会交互询问：数据库类型、主机、端口、库名、账号、密码和 Web 端口。也可以先准备环境变量：

```bash
export ZBXTABLE_DB_TYPE=mysql
export ZBXTABLE_DB_HOST=127.0.0.1
export ZBXTABLE_DB_PORT=3306
export ZBXTABLE_DB_NAME=zabbix
export ZBXTABLE_DB_USER=zbxtable_runtime
export ZBXTABLE_DB_PASS='数据库密码'
export ZBXTABLE_HTTP_PORT=8088

sudo -E bash install-release.sh \
  --version=v3.0.7 \
  --install-deps \
  --install-root=/opt/zbxtable
```

建议使用独立的 `zbxtable_runtime` 数据库账号，而不是直接使用 Zabbix 管理员账号。

### 3.4 启动和检查服务

```bash
sudo systemctl daemon-reload
sudo systemctl enable zbxtable
sudo systemctl start zbxtable
sudo systemctl status zbxtable --no-pager
sudo journalctl -u zbxtable -n 100 --no-pager
```

访问：

```text
http://服务器IP:8088
```

如果端口被占用，修改 `/opt/zbxtable/config/app.conf` 的 `httpport`，然后执行：

```bash
sudo systemctl restart zbxtable
```

## 4. 方式二：上传完整压缩包到 Linux

### 4.1 上传并校验

在 Windows PowerShell、Linux 或 macOS 本地执行：

```bash
scp dist/zbxtable-v3.0.7-source.tar.gz \
  dist/zbxtable-v3.0.7-source.tar.gz.sha256 \
  user@server:/tmp/
```

登录服务器：

```bash
ssh user@server
sha256sum -c /tmp/zbxtable-v3.0.7-source.tar.gz.sha256
```

### 4.2 解压并一键安装

```bash
sudo mkdir -p /opt/zbxtable
sudo tar -xzf /tmp/zbxtable-v3.0.7-source.tar.gz \
  -C /opt/zbxtable --strip-components=1

cd /opt/zbxtable
sudo bash scripts/bootstrap-linux.sh
sudo env \
  ZBXTABLE_DB_TYPE=mysql \
  ZBXTABLE_DB_HOST=127.0.0.1 \
  ZBXTABLE_DB_PORT=3306 \
  ZBXTABLE_DB_NAME=zabbix \
  ZBXTABLE_DB_USER=zbxtable_runtime \
  ZBXTABLE_DB_PASS='数据库密码' \
  ZBXTABLE_HTTP_PORT=8088 \
  bash scripts/install.sh

sudo systemctl start zbxtable
```

如果服务器已经具备 Go 1.24+ 和所需工具，可以跳过 `bootstrap-linux.sh`。如果只想检查而不安装环境，直接执行 `bash scripts/install.sh`，脚本会在缺少依赖时给出错误。

### 4.3 直接上传 3.0.7 目录

```bash
scp -r dist/zbxtable-v3.0.7 user@server:/tmp/
ssh user@server
sudo rm -rf /opt/zbxtable
sudo mv /tmp/zbxtable-v3.0.7 /opt/zbxtable
cd /opt/zbxtable
sudo bash scripts/bootstrap-linux.sh
sudo bash scripts/install.sh
sudo systemctl start zbxtable
```

使用目录部署时，建议先编辑 `config/app.conf` 或通过环境变量提供数据库密码，避免密码出现在命令历史中。

## 5. 方式三：Linux 前后端分别部署

ZbxTable 的 Go 后端通过 `go:embed` 读取 `api/v1/web/web/`。生产环境推荐先构建前端，再把构建结果复制到后端目录，最后编译后端。这样部署后只运行一个后端服务，浏览器访问同一个端口。

### 5.1 单独准备前端

```bash
git clone --branch 3.0 --depth 1 \
  https://github.com/canghai908/zbxtable-web.git /opt/zbxtable-web
cd /opt/zbxtable-web

if [ -f yarn.lock ] && command -v yarn >/dev/null 2>&1; then
  yarn install --frozen-lockfile
  yarn build
else
  npm ci
  npm run build
fi
```

把构建结果复制到后端：

```bash
rm -rf /opt/zbxtable/api/v1/web/web
mkdir -p /opt/zbxtable/api/v1/web/web
cp -a /opt/zbxtable-web/web/. /opt/zbxtable/api/v1/web/web/
```

如果前端输出目录是 `app/build`，使用：

```bash
cp -a /opt/zbxtable-web/app/build/. /opt/zbxtable/api/v1/web/web/
```

### 5.2 编译和运行后端

```bash
cd /opt/zbxtable
go mod download
CGO_ENABLED=0 go build -trimpath -ldflags='-s -w' \
  -o build/zbxtable ./main.go
bash scripts/run.sh
```

如果只部署 API、由独立前端或反向代理提供页面，可以跳过前端：

```bash
ZBXTABLE_SKIP_FRONTEND=1 bash scripts/install.sh
```

## 6. 方式四：Windows 部署

### 6.1 从 Release 自动下载

以管理员 PowerShell 执行：

```powershell
iwr https://github.com/linguyuebai/zbxtable/releases/latest/download/install-release.ps1 `
  -OutFile install-release.ps1

powershell.exe -ExecutionPolicy Bypass `
  -File .\install-release.ps1 `

```

Windows 安装器会校验 ZIP 的 SHA256，目标目录存在时默认停止，使用 `-Force` 才替换。安装后运行：

```powershell
powershell.exe -ExecutionPolicy Bypass `
  -File C:\ProgramData\zbxtable\scripts\run.ps1
```

### 6.2 从 ZIP 手动部署

```powershell
Expand-Archive .\zbxtable-v3.0.7-source.zip `
  -DestinationPath C:\Temp\zbxtable
cd C:\Temp\zbxtable\zbxtable-v3.0.7
Copy-Item config\app.conf.example config\app.conf
notepad config\app.conf
powershell.exe -ExecutionPolicy Bypass -File .\scripts\install.ps1
powershell.exe -ExecutionPolicy Bypass -File .\scripts\run.ps1
```

## 7. 数据库共用和权限配置

### 7.1 MySQL/MariaDB

如果 Zabbix 和 ZbxTable 使用同一个数据库：

```sql
CREATE USER 'zbxtable_runtime'@'127.0.0.1'
  IDENTIFIED BY '请替换为强密码';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX
  ON zabbix.* TO 'zbxtable_runtime'@'127.0.0.1';
FLUSH PRIVILEGES;
```

如果数据库连接来自独立应用服务器，把 `127.0.0.1` 替换为固定的应用服务器地址，并限制防火墙来源。不要把密码写入 Git、Release 资产或公开截图。

### 7.2 PostgreSQL

```sql
CREATE USER zbxtable_runtime WITH PASSWORD '请替换为强密码';
GRANT CONNECT ON DATABASE zabbix TO zbxtable_runtime;
GRANT USAGE ON SCHEMA public TO zbxtable_runtime;
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE
  ON ALL TABLES IN SCHEMA public TO zbxtable_runtime;
GRANT USAGE, SELECT, UPDATE
  ON ALL SEQUENCES IN SCHEMA public TO zbxtable_runtime;
```

首次启动后检查数据库中是否生成 `zbxtable_` 开头的表。不要手工修改这些表的结构；升级时由应用迁移逻辑处理。

## 8. Zabbix API 和巡检配置

1. 在 Zabbix 中文界面创建只读巡检用户或 API Token。
2. 在 ZbxTable 中添加 Zabbix 实例，填写 API URL，例如 `https://zabbix.example.com/api_jsonrpc.php`。
3. 测试 API 连接，确认可以读取主机、监控项、历史数据和事件。
4. 进入“报表/设备巡检”，创建巡检策略，选择主机或主机组。
5. 配置 IP、主机名、CPU、内存、磁盘、剩余容量、时间同步和安全日志监控项。
6. 设置 `inspection_enabled=1` 和 `inspection_cron`，或先使用“立即巡检”验证。
7. 使用导出功能生成 Excel 巡检表。

报表规则：百分比和数值保留两位小数；日报可查看明细；周报、月报按设备和指标输出周期平均值，不展示每天的逐条数值。巡检结果、汇总和导出接口详见《Zabbix 巡检与 Windows 日志对接指南》。

常用接口：

```text
GET  /v1/inspection/policies/:id/results
GET  /v1/inspection/policies/:id/summary?start=...&end=...
POST /v1/inspection/export
```

## 9. Windows/Linux 日志和告警

Windows Security 日志建议采集事件 4624、4625、4648、4672、4720、4740，用于识别异常账号、非常用 IP、登录失败、暴力破解和账号锁定。Linux 采集 `/var/log/auth.log` 或 `/var/log/secure` 中的 `Failed password`、`Accepted password` 和 `authentication failure`。

在 Zabbix 中文界面创建日志监控项，等待历史数据后再配置巡检策略。进入“管理 → 报警 → 媒体类型”配置 SMTP，在用户媒体中填写收件人，再在动作中匹配登录失败、暴力破解、时间同步异常和巡检告警。

完整的 Windows EventLog 键值、Zabbix 触发器、邮件测试、微信/Webhook 和异常 IP 规则见：[Zabbix 巡检与 Windows 日志对接指南](./Zabbix-巡检与Windows日志对接指南.md)。

## 10. Nginx HTTPS 反向代理（可选）

```nginx
server {
    listen 443 ssl http2;
    server_name zbxtable.example.com;

    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8088;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
sudo nginx -t
sudo systemctl reload nginx
```

外部只开放 443；8088 只允许本机或内网访问。Zabbix API Token、数据库密码和 SMTP 授权码应放在受保护的配置文件中。

## 11. 升级、回滚和备份

升级前：

```bash
sudo systemctl stop zbxtable
sudo cp -a /opt/zbxtable/config/app.conf /root/app.conf.zbxtable.backup
mysqldump --single-transaction zabbix > /root/zabbix-before-zbxtable-upgrade.sql
```

安装新版本时使用新的 `--install-root` 临时目录，确认配置和报告正常后再切换；或者使用 `--force` 替换程序文件。不要删除旧版本配置，不要直接覆盖 Zabbix 数据库。出现问题时停止新服务，恢复旧目录和 `config/app.conf`，再启动旧版本。

## 12. 一键卸载

一行彻底卸载 3.0.7（停止并删除 ZbxTable 服务、程序、配置和运行文件，不删除 Zabbix 数据库及 Zabbix 服务）：

```bash
curl -fsSL https://github.com/linguyuebai/zbxtable/releases/download/v3.0.7/uninstall.sh | sudo bash -s -- --install-root=/opt/zbxtable --runtime-root=/usr/local/zbxtable --purge --yes
```

默认卸载程序和运行文件，保留 `config/app.conf`：

```bash
sudo bash /opt/zbxtable/scripts/uninstall.sh \
  --install-root=/opt/zbxtable --runtime-root=/usr/local/zbxtable --yes
```

彻底删除 ZbxTable 配置和文件：

```bash
sudo bash /opt/zbxtable/scripts/uninstall.sh \
  --install-root=/opt/zbxtable --runtime-root=/usr/local/zbxtable \
  --purge --yes
```

卸载不会删除 Zabbix 数据库、Zabbix 原生表、Zabbix Server 或 Agent。安装创建的 `zbxtable` 系统用户默认保留，确认无其他用途后再手工删除。

## 13. 常见故障排查

### 端口被占用

```bash
sudo ss -ltnp | grep ':8088'
```

修改 `httpport` 后重启 ZbxTable，不要修改正在使用的 Zabbix 端口。

### 数据库连接失败

检查 `dbtype`、`dbhost`、`dbport`、`dbname`、`dbuser` 和密码；确认数据库允许应用服务器来源地址；检查账号权限和防火墙。

### 前端空白或 404

确认 `api/v1/web/web/index.html` 存在；重新运行 `bash scripts/prepare-frontend.sh`，或重新下载完整 TAR.GZ。只运行 API 模式时，需要由独立前端或反向代理提供页面。

### 服务启动失败

```bash
sudo journalctl -u zbxtable -n 200 --no-pager
sudo systemctl cat zbxtable
```

重点检查配置文件权限、端口、数据库密码、API 地址和 Go 构建是否成功。

### 巡检没有数据

确认 Zabbix API Token 有权限读取目标主机和监控项；确认日志监控项已经产生历史数据；手动执行一次巡检；再检查 `GET /v1/inspection/policies/:id/results` 和应用日志。

### 邮件没有收到

先在 Zabbix 媒体类型中测试 SMTP，再检查用户媒体、动作条件、严重性和告警时间段。不要只检查 ZbxTable 页面状态，要同时查看 Zabbix 事件和动作日志。
