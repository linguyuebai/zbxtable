# 安装向导：数据库检测与创建

ZbxTable 是 Zabbix 的管理和报表扩展，不会替代 `zabbix-server`，也不会修改 Zabbix 的 `hosts`、`items`、`history`、`events` 等原生表。安装向导配置的是 **ZbxTable 自己的运行数据库**；Zabbix API 对接在安装完成后于“系统设置 → Zabbix 实例”中添加。

一键安装脚本安装的是 ZbxTable 程序、Go 运行环境和 systemd/Docker 运行组件，不会盲目安装或替换 MySQL/PostgreSQL 服务，因为这可能覆盖现有 Zabbix 数据库。它会使用现有数据库服务创建 ZbxTable 数据库；如果服务器上还没有数据库服务，请先按 Zabbix 官方文档安装并启动 MySQL/MariaDB 或 PostgreSQL。

## 自动创建和隔离

首次安装默认数据库名为 `zbxtable_lg`。提交安装配置时，程序会：

1. 检测 Linux/Windows 运行平台和 CPU 架构。
2. 连接指定的 MySQL/MariaDB 或 PostgreSQL 服务器，列出已有数据库，并标记名称中包含 `zabbix` 的数据库。
3. 如果 `zbxtable_lg` 不存在，使用安装时填写的数据库账号创建它，然后只在该库中创建 `zbxtable_*` 表。
4. 如果管理员明确填写现有的 `zabbix` 数据库，程序不会创建、删除或修改 Zabbix 原生表，只创建 `zbxtable_*` 表。生产环境建议使用独立库和独立账号。

创建数据库需要账号具备 `CREATE DATABASE` 权限。也可以先由 DBA 手工创建 `zbxtable_lg`，再使用仅拥有该库读写和建表权限的账号完成安装。

## 安装向导接口

安装页面使用以下无需登录的接口：

| 接口 | 作用 |
| --- | --- |
| `POST /install/database-info` | 只读检测操作系统、数据库类型、可见数据库和可能的 Zabbix 数据库；不会修改数据。 |
| `POST /install/check-db` | 测试目标数据库连接；传 `create_database:true` 时，如果目标库不存在则创建。 |
| `POST /install/install` | 写入配置并自动创建不存在的目标库，然后迁移 ZbxTable 表。 |

示例：

```bash
curl -sS http://127.0.0.1:8089/install/database-info \
  -H 'Content-Type: application/json' \
  -d '{"dbtype":"mysql","dbhost":"127.0.0.1","dbport":"3306","dbuser":"root","dbpass":"密码"}'

curl -sS http://127.0.0.1:8089/install/install \
  -H 'Content-Type: application/json' \
  -d '{"dbtype":"mysql","dbhost":"127.0.0.1","dbport":"3306","dbuser":"root","dbpass":"密码","dbname":"zbxtable_lg","httpport":"8089"}'
```

成功响应会返回 `database`、`database_created` 和 `zabbix_database_unchanged`，便于安装脚本和页面向用户显示实际结果。

## 与 Zabbix 对接

安装完成并重启服务后，在页面中新增 Zabbix 实例，填写 Zabbix Web/API 地址、账号密码或 API Token，点击“测试连接”。ZbxTable 通过 Zabbix API 读取主机、监控项、历史数据和日志，不需要直接写入 Zabbix 数据库。删除实例只删除 ZbxTable 的连接配置，不会删除 Zabbix 服务或数据库。
